Onboarding guide

From a fresh clone to your first shipped PR.

Agentic Workflow gives your AI coding agent a shared set of skills, safety rails, and tools. It works the same way in Claude Code, Codex, and Cursor. Install it once and it's available in every repo.

$Terminal

Blocks labeled terminal run in your shell (zsh, bash): ./setup.sh, git pull, scorer --since 7d.

›Agent session

Skills like bootstrap and review run inside the agent. Start claude, codex, or cursor-agent in the repo, then type them at its prompt.

Heads upTyping a skill into your terminal fails with zsh: no such file or directory: /prismStatus. The shell reads it as a file path. Run it at the agent's prompt instead.

Pick your agent CLI in the top-right corner. Every command on this page updates to use your CLI's skill syntax (/).

01 · The toolkit

What you get

Everything is installed globally, so it's in every agent session on your machine.

Skills

Packaged workflows you trigger by name: officeHours, review, rootCause, shipRelease, and more.

Safety hooks

Block rm -rf, git reset --hard, force-pushes, pushes to main, and commands that contain secrets, before they run.

MCP servers

serena symbol search · agentic-bridge agent-to-agent messaging · prism-mcp memory · headroom compression · xcodebuildmcp iOS

Token savers + scorer

rtk rewrites noisy shell commands. headroom compresses big reads. scorer reports what your sessions cost.

02 · About 15 minutes

Install

Three steps. setup.sh finds the agent CLIs on your PATH and installs for each one.

Install the prerequisites

You need at least one agent CLI (claude, codex, or cursor-agent), plus:

$ brew install jq gh node python $ gh auth login

Also install Docker Desktop and keep it running. Serena runs in Docker. Setup installs rtk and headroom for you.

Clone and preview

--dry-run prints every change without writing anything.

$ git clone https://github.com/vitalizecare/agentic-workflow.git ~/repos/agentic-workflow $ cd ~/repos/agentic-workflow $ ./setup.sh --dry-run

Run setup

$ ./setup.sh # or: ./setup.sh --providers claude,codex,cursor

Then do the last step for your CLI:

Nothing else to do. Setup also installs the statusline and shell integration. Open a new terminal so they load.

Trust the hooks. Codex only runs hooks you've approved:

$ codex › /hooks # trust every aw:* entry

Repeat this after any reinstall that changes a hook.

Enable MCP servers if Cursor asks for approval on first use:

$ cursor-agent mcp enable serena # repeat per server

03 · Check your setup

Check it worked

Open a new agent session in any git repo (cd into it and run claude, codex, or cursor-agent) and tick each item off. Your progress is saved in this browser and shown in the top bar.

Something wrong?

Click a symptom to see the fix.

MCPserena fails to connect
Docker isn't running. Start Docker Desktop, then restart the agent session.
WARN“prism-mcp dashboard unreachable at :7180”
The Mind Palace dashboard isn't up. This only affects memory features, so everything else still works. Run prismStatus in your agent session for details.
SHELLzsh: no such file or directory: /prismStatus
You typed a skill into your terminal. Skills run inside the agent: start claude (or codex, cursor-agent), then type prismStatus at its prompt.
SKILLSSkills missing in Codex or Cursor
Re-run ./setup.sh --providers <name>, then check that ~/.agentic-workflow/providers lists your provider.
HOOKSHooks do nothing in Codex
You haven't trusted them yet. Open codex, run /hooks, and trust every aw:* entry.
SKILLSA skill says “toolkit not installed”
~/.agentic-workflow/toolkit is missing or broken. Re-run ./setup.sh from your clone.
WARNjudge warning at session start
Run judge health. Judge needs at least one of claude, codex, or cursor-agent on your PATH.
MCPgithub MCP auth errors
Re-authenticate with gh auth login. Skills fall back to the gh CLI when the MCP server is unavailable.

04 · Once per repo

Bootstrap a repo

Start an agent session in the repo you want to work in, then run one skill. It checks what documentation exists and writes the rest, adapted to your stack. Commit the output so every future session starts with the same context.

› bootstrap # --force regenerate docs that already exist # --product-docs <url|path> pull in Confluence, SharePoint, or drive docs
your-repo/ ├── AGENTS.md what every agent reads first ├── CLAUDE.md → symlink to AGENTS.md ├── .agents/rules/ rules scoped by glob ├── .claude/rules → linked for Claude ├── .cursor/rules/ → linked for Cursor ├── planning/ architecture, ERD, style… └── .serena/ turns on symbol navigation

08 · Files

Where things live

Skill output lives outside your repo, so it never clutters git status. Treat plan files as short-lived: once the plan is in GitHub issues, the issues are the source of truth.

~/.agentic-workflow/ ├── toolkit → symlink to your clone; skills read shared files through it ├── providers one line per installed provider ├── scorer/reports/ cost and involvement reports └── <repo-slug>/ ├── plans/<feature>/ plan.md · product.md · engineering.md · design-brief.md · TASKS.md ├── reviews/<pr>.json review state, the source of truth for postReview and addressReview └── … evidence packs, design baselines, grouped by domain

09 · When you're comfortable

Extras & staying up to date

See what sessions cost

Reports land in ~/.agentic-workflow/scorer/reports/.

$ scorer --since 7d

Coordinate agents

With agentic-bridge, one session can assign a task to another, even across providers. Messages queue while the recipient is offline.

Trim skills per repo

Claude Code only. Profiles: web-app, ios, personal.

$ ./setup.sh --profile web-app \ --target ~/repos/app

Tune the judge

judge lets you inspect, tune, and undo the decisions it made for hooks: why, undo, health.

Update

$ cd ~/repos/agentic-workflow && git pull && ./setup.sh

Skills are symlinks, so skill text updates as soon as you pull. Re-run setup to pick up new hooks, MCP servers, and builds. In Codex, re-trust any hooks that changed with /hooks.

More detail: README.md · planning/PROVIDERS.md · skills/_shared/capabilities.md · each skill's full instructions are in skills/<name>/SKILL.md. A plain-text version of this guide is in ONBOARDING.md.
